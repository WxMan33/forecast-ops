# Daily blend investigation flags

Small buttons under the calendar date open inline supporting guidance. Existing temperature record badges remain in the low/high cells. These screens change no forecasts, weights or verification records. The optional IFS 9 km visibility request is separate from blend contributors. HRRR visibility uses its existing request; CVG RRFS visibility comes from the same native GRIB run as its point forecast.

- **AM fog? / AM vis↓**: 03:00–08:59 local; at least one named model at the selected point or a local airport must predict ≤3 statute miles at two consecutive upcoming hourly samples. Only dry/trace hours qualify: liquid precipitation ≤0.001 in., no snowfall >0.001 in. and no rain/snow weather code (51–99). Missing precipitation cannot qualify. AM fog? additionally requires 0–3.6°F temperature/dew-point spread in that same model at two consecutive qualifying samples. Otherwise AM vis↓ identifies non-precipitation low visibility with uncertain cause. Humidity/light wind alone never creates either flag.
- **Frost?**: 00:00–08:59 local; air temperature ≤36°F, temperature minus dew point 0–8°F, wind 0–5 mph, total cloud cover 0–50%. Same-source persistence and two-source requirements as fog. Surface, soil and valley temperatures are not diagnosed.
- **Freeze?**: 00:00–08:59 local; air temperature ≤32°F in at least two consecutive hourly samples in at least two sources. Replaces the frost badge when this temperature screen qualifies. Not an official advisory or a claim about frost formation, vegetation or growing season.
- **G:20+, G:30+, …**: upcoming blended peak hourly gust in mph, grouped into 10-mph bands from 20 mph. Uses the same weights and aggregation as the daily table; for today, only the remaining hourly window is aggregated, so an earlier gust peak cannot create this cue. Not an NWS advisory threshold.

Fog flags require the named visibility sources; frost/freeze screens inspect loaded deterministic and NWS sources independently of slider settings. Ensemble hourly means are excluded because joint conditions in their average need not occur in any individual member. Inputs must be finite numbers; missing variables cannot become zero, calm, clear or saturated. Sample pairs must be exactly one hour apart on the UTC axis, including across DST. Only the current hour onward is considered when rendered. Each flagged date refers to that date's morning, not the following morning. Refresh updates the assessment. There is no background notification timer.

Details name supporting sources and qualifying hourly samples, explain the thresholds, report the number of sources with at least a usable two-sample segment, and disclose incomplete coverage. This denominator is not full-morning coverage or a probability. Different sources can support different hours. Longer-lead flags are preliminary, and no flag is not an all-clear. Thresholds are provisional project screening choices, not calibrated event probabilities.

Physical background: [NWS frost formation](https://www.weather.gov/arx/why_frost) and [NWS dew/frost training](https://www.weather.gov/source/zhu/ZHU_Training_Page/fog_stuff/Dew_Frost/Dew_Frost.htm) explain the roles of clear skies, light wind, moisture and surface cooling below shelter-level temperature. These sources support the ingredients, not the project's exact thresholds or skill.

Validation: `node tests/impact-flags.test.js`; existing planning-clock/weights and record-watch tests; `tests/forecast-focus-browser.py` exercises inline expansion, keyboard activation and 360/390/1440-pixel layouts with synthetic flag-producing guidance. The browser cases run in CI with the existing dashboard tests.

## Visibility support

For the upcoming 3–9 AM window, details compare HRRR, deterministic RRFS and separately loaded ECMWF IFS 9 km visibility at the selected forecast point. Stored values are metres, explicitly normalized from the provider's reported units (imperial Open-Meteo requests return feet). Unknown units, negative values, nulls and out-of-range values remain unavailable; zero is valid. Display uses statute miles. The IFS 0.25° and AIFS feeds returned no visibility in real CVG probes, so neither is substituted for IFS 9 km.

A single named visibility model can add a heads-up with at least two consecutive upcoming hourly samples ≤3 statute miles. Rain/snow hours are excluded before applying the visibility gate. At dry qualifying hours, 0–3.6°F temperature/dew-point spread provides additional fog support without imposing a wind limit on advection fog. Without moisture support, use AM vis↓ instead of claiming fog. The former two-source humidity/light-wind fallback is removed: neither a fog nor limited-visibility badge appears without qualifying visibility. Fog ingredients must occur in the same visibility source and at the same qualifying hours; humidity in another model cannot change a rain-obscured visibility forecast into a fog diagnosis. This does not diagnose smoke, snow, rain or other obscurations and is not a calibrated probability or advisory. Provider hourly samples can be interpolated from coarser output, especially at longer leads.

Each source lists the morning minimum and its sample times, sustained ≤3-mile hours, fog-supporting hours, available/expected upcoming samples, retrieval time and confirmed native cycle when available. A decrease of at least 1 mile from a known earlier value in the prior six model-forecast hours is shown within that same series. Earlier values are forecasts, not observations or comparisons with a previous model run. Missing data never becomes good visibility or a claimed change. Cincinnati's default CVG point is not an area-wide minimum and does not represent every valley.

Native RRFS VIS is optional: validate GRIB discipline/category/number 0/19/0, surface level 0, instantaneous start/end step matching the requested forecast hour, hourly step units and metres. Failure leaves an unknown visibility hour while temperature, precipitation and ensemble collection continue. Existing complete same-cycle feeds are upgraded with deterministic VIS only, preserving their other forecast values and carrying their prior checksum evidence forward. Subsequent cycles collect VIS with the deterministic fields; ensemble visibility is not claimed.

Live probes on Nov 5, 2026 confirmed HRRR/provider RRFS visibility with feet units, IFS 0.25° null visibility and IFS 9 km numeric visibility. A native NOAA RRFS 18Z f001 CVG sample decoded 33,994.17 metres with exact parameter/time validation and retained GRIB byte-range checksum. See captured visibility fixtures and unit/screen regression tests.

References: https://open-meteo.com/en/docs/ecmwf-api (9 km native visibility, unlike 0.25°); https://open-meteo.com/en/docs/gfs-api (NOAA visibility); https://repository.library.noaa.gov/view/noaa/72271/noaa_72271_DS1.pdf (HRRR/RRFS visibility diagnostics). The ≤3-mile/persistence screen is a project investigation threshold, not a documented skill claim.

Regression: the reported HRRR 8.5 mi, RRFS 8.7 mi and IFS 9 km 17.4 mi morning minima produce no fog/visibility flag even with multiple moist, calm sources. Node and browser tests cover this case, missing visibility, a single isolated low sample, the inclusive 3-mile boundary, and retaining independent frost screening.

## Cincinnati airport comparison

When the selected point is within 80 km of CVG, also screen CVG, LUK (Lunken Field), HAO (Butler County Regional) and MWO (Middletown/Hook Field). A site within 3 km of the selected point is not fetched twice; custom points remain separately identified. NWS station coordinates: https://api.weather.gov/stations/KLUK, https://api.weather.gov/stations/KHAO, https://api.weather.gov/stations/KMWO. CVG retains the existing pilot coordinates.

Three batched requests, one per named visibility model, cover the other airports for three forecast days. Each batch validates response count, location identity/order, grid proximity and unit metadata before alignment on true UTC instants. Cache and retrieval times use the existing loader. Failed sources remain absent rather than inheriting CVG conditions. Outside the Cincinnati pilot region no local-airport requests are made. Airport series do not enter blend weights, forecast rows, or verification archives. Native CVG RRFS remains the preferred same-run feed at the selected CVG point; other airports use explicitly named provider point guidance with no confirmed run claim.

Flags identify qualifying airport codes, e.g. AM fog? · LUK while CVG stays clear. More than two sites are compacted to the first two codes plus a count; the hover/detail lists qualifying location names and each airport/model value. All samples represent model grid cells, not observations, exact valley minima or spatial coverage. Coarser grids may still miss valley fog.

Tests reproduce a clear CVG with fog only at LUK, remove flags when that LUK low visibility is accompanied by rain/snow or missing precipitation, and keep the independent frost screen. Browser tests exercise the actual batch loader, source labels, positive/negative flags and 360/390/1440-pixel details. A captured real three-airport HRRR response validates units and geographic identity.

## Compact airport presentation

The expanded heads-up groups qualifying guidance by airport. Each airport lists only models with sustained qualifying low visibility, their minimum across qualifying hours and the supporting sample window. Airports without a qualifying signal appear on a single coverage-qualified line. Full morning minima, source/run metadata and unavailable values remain in a closed “Full values & source details” disclosure. Screening thresholds and blend calculations are unchanged.
